# Plan: Spec 002 — Proof Pipeline and Solidity Verifier

**Spec:** [spec.md](spec.md)
**Status:** approved

## Technical approach

The full pipeline was smoke-tested end-to-end on the installed toolchain before this plan was written (u64 variant): witness via `nargo execute`, proof via `bb prove` targeting the EVM, local verification, backend gate counts, and Solidity verifier generation all work. The plan generalizes that verified flow to the four variants with reproducible scripts, then adds the Foundry project and the anvil Sepolia-fork deployment.

Verified CLI facts (bb 5.0.0-nightly.20260324 — flags differ from older bb docs):

- `bb prove -b target/<pkg>.json -w target/<pkg>.gz -o <dir> -t evm --write_vk` emits `proof`, `public_inputs`, `vk`, `vk_hash`.
- `-t/--verifier_target evm` selects keccak + ZK settings for Solidity verification (native default is poseidon2). The EVM pipeline must use `-t evm` consistently for prove/verify/vk.
- `bb verify -t evm -k vk -p proof -i public_inputs` returns success on the smoke test.
- `bb gates -b <bytecode>` reports `acir_opcodes` and `circuit_size` (backend gates).
- `bb write_solidity_verifier -k vk -o Verifier.sol` emits a ZK Honk verifier (~100 KB source; bytecode size is the EIP-170 concern, measured after compilation). The verifier embeds the VK, so one contract is generated per variant.
- `bb proof_stats -p proof` available for compressed-size/public-input statistics.

Smoke-test measurements (canonical inputs `v=50, a=10, b=100`, identical across variants):

| Variant | ACIR opcodes | Backend gates (`circuit_size`) |
|---------|--------------|--------------------------------|
| field | 5 | 40 |
| u8 | 11 | 93 |
| u32 | 11 | 2791 |
| u64 | 11 | 2838 |

Backend gates strongly differentiate bit-widths while ACIR stays flat — with a 30x jump between u8 and u32 (lookup machinery threshold), not a linear growth. u64 proof: 7,232 bytes; public inputs 64 bytes; vk 1,888 bytes. These findings go to the research log and shape the analysis narrative.

## Stack and versions

- `nargo` 1.0.0-beta.20, `bb` 5.0.0-nightly.20260324 (bbup-paired), Foundry 1.1.0-stable.
- Sepolia RPC for forking: configurable via `SEPOLIA_RPC_URL` env var (default: a public endpoint, documented in the script; only affects setup, never results).

## Design

```
scripts/collect-circuit-metrics.sh   # extended: fills backend_gates via bb gates (closes spec 001 pending)
scripts/prove-all.sh                 # per variant: nargo execute -> bb prove -t evm --write_vk -> bb verify
                                     # -> results/proofs/<variant>/ + results/proof-metrics.json (sizes in bytes)
contracts/                           # Foundry project
  foundry.toml                       # optimizer enabled, optimizer_runs = 1 (EIP-170 tuning per methodology)
  src/<Variant>Verifier.sol          # generated by bb write_solidity_verifier (one per variant)
  test/Verifier.t.sol                # forge tests: valid proof accepted, mutated proof rejected (FFI or fixture-based)
  script/Deploy.s.sol                # deployment to the anvil Sepolia fork
scripts/deploy-fork.sh               # starts anvil --fork-url $SEPOLIA_RPC_URL, deploys, runs a valid
                                     # verification tx and a corrupted one, reports bytecode sizes
```

- Canonical proof inputs fixed at `v=50, a=10, b=100` for all variants (gitignored `Prover.toml` files are generated by the script, keeping inputs identical and reproducible).
- Proof fixtures for Foundry tests are produced by `prove-all.sh` and read from `results/proofs/` (paths documented; fixtures small enough to commit — decision recorded in tasks).
- EIP-170: measure with `forge build --sizes`; if any verifier exceeds 24,576 bytes at `optimizer_runs = 1`, implement the split-verifier topology; either way, record the outcome in the research log (methodology Fase 1 requires making this constraint explicit).
- `CLAUDE.md` command reference updated to the verified bb syntax (the current reference predates the probe).

## Risks and mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| bb nightly CLI drift on future reinstall | scripts break | exact version pinned in CLAUDE.md; scripts fail loudly; bbup pairing recorded |
| Verifier bytecode > EIP-170 even at optimizer_runs=1 | deploy blocked | split-verifier fallback planned by the methodology; measured before deploy step |
| Public RPC rate limits during fork | flaky deploys | fork started once per session; RPC configurable; retries documented |
| `-t evm` (keccak) proving cost differs from native default (poseidon2) | benchmark design ambiguity later | flagged now for specs 003/004: environment comparison must fix one target; logged in research log as an open methodological decision |

## Verification plan

1. `scripts/prove-all.sh` runs clean for all four variants: 4 proofs generated and locally verified, `results/proof-metrics.json` written with sizes.
2. `scripts/collect-circuit-metrics.sh` now emits nonzero `backend_gates` for all variants (`backend_gates_status: collected`).
3. `forge build --sizes` reports every verifier's bytecode size; all ≤ 24,576 bytes or split-verifier in place.
4. `forge test` passes: valid fixture accepted, mutated fixture rejected.
5. `scripts/deploy-fork.sh` against a Sepolia fork: deployment succeeds, valid verification tx succeeds, corrupted proof tx reverts.
